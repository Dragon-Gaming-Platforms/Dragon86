# system-apps — apps that ship with the OS

Each folder here is a **filesystem app**: on first boot the OS copies it into
`~/system/apps/<id>/`, and from then on the guest and the Files app see the
same files. The `index.json` in each folder lists the files to copy — it is
the only thing this directory is for; delete a folder here and existing
devices keep their copy (their filesystem is the source of truth now).

| app          | what it is |
|--------------|------------|
| `preview`    | The default app for pictures, sound, video, PDFs, 3D models and ISO disc images (see below). Claims every one of those types, and ships with `"desktop": false`. |
| `nes`        | jsnes (Apache-2.0, `LICENSE.jsnes`) running `test.nes`, a ROM generated by `tools/make-test-rom.py` — no commercial ROM is bundled. Claims `.nes`. |
| `snake`      | A small grid game; installable from the App Store. |
| `calculator` | Four-function calculator; installable from the App Store. |

The App Store (`public/store.json`) lists `snake` and `calculator` as
downloadable apps; they live here so the catalog can install them from the
same origin, and `nes` and `preview` count as already installed on a device
that has booted once.

## The manifest

`user-apps.json` (and an App Store listing) understands these fields:

```json
{
  "id": "my-app",                  // unique, lowercase; also the folder name
  "name": "My App",
  "sub": "Short subtitle",         // start menu / store subtitle
  "icon": "browser",               // a built-in glyph name, or "img:icons/x.png"
  "icon-path": "icon.svg",         // image inside the app folder (wins over "icon")
  "entry": "index.html",
  "title-template": "My App - {file}",  // window title when opening a file
  "desktop": false,                // start with no desktop icon (default true)
  "folder-isolated": true,
  "opens": ["txt"],
  "width": 640,
  "height": 480
}
```

`icon-path` is resolved through the app's own `9pf/<id>/` route, so the file
must be inside the app folder — `"icon-path": "icon.svg"` shows
`~/system/apps/my-app/icon.svg`. That is what the desktop icon, the start
menu and the App Store card all draw, which is why the bundled apps ship an
`icon.svg` next to their code.

`desktop` is only the *starting* state. The desktop is a shelf you arrange:
**Remove from Desktop** in an app icon's menu takes the icon away without
uninstalling anything (the app stays in the start menu), **Add to Desktop**
on the app's own page — right-click its `index.html` in Files — puts it back,
and Settings → Apps has a switch per app. The choice is stored in
`~/system/desktop-apps.json`, not in the browser, so it survives a cleared
profile and is visible in Files like any other user data.

`title-template` only applies when the app is opening a file: `{file}` is
replaced with the file's name, so Preview's window reads
`Preview - holiday.png` instead of a bare app name.

To make your own: add `~/system/apps/my-app/` with an `index.html`, then an
entry in `~/system/apps/user-apps.json`:

```json
{ "id": "my-app", "name": "My App", "entry": "index.html", "folder-isolated": true, "opens": ["txt"] }
```

`opens` is optional: it says which file types the app can handle (Preview
claims about forty of them — one toast asks about the whole set, not one per
type), which is
what makes it appear under **Open with ›** and lets it ask to be the default
(for example, an emulator claiming `nes`). An app that claims a type receives
the file it was asked to open as `?file=<absolute path>` on its entry URL:

```js
const requested = new URL(location.href).searchParams.get("file");
```
